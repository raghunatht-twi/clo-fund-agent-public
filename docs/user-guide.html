Introduction

What Is the CLO Fund Agent?

The DKIG CLO Fund Agent is an AI-powered analytics system that lets you ask plain-English questions about Collateralised Loan Obligation (CLO) fund data and receive structured, cited answers in seconds. It combines Anthropic's Claude Sonnet 4.6 model with a structured tool layer that reads from either an Excel workbook or a PostgreSQL database.

The system exposes four entry points — a terminal REPL, a one-shot CLI, a REST API, and a browser chat UI — all backed by the same eight canonical data products (DP-01 through DP-08). A separate multi-agent orchestrator handles complex cross-product analysis tasks by dispatching specialist sub-agents in parallel.

Natural Language Q&A

Ask in plain English. No SQL, no spreadsheets. The agent calls the right tools automatically.

Always Cited

Every number is attributed to a fund ID, data product, and reporting date. Hallucination safeguards built in.

Compliance-Aware

OC/IC covenant status is checked automatically before equity distribution questions are answered.

Portfolio Optimizer

Greedy hill-climbing optimizer finds trade sequences that improve equity yield while keeping all tests passing.

Multi-Agent

Complex tasks are decomposed and dispatched to specialist agents — portfolio, compliance, cashflow, fees, and more — running in parallel.

Getting Started

Prerequisites & Setup

Requirements

  • Python 3.12 or higher
  • uv package manager (astral-sh/uv)
  • ANTHROPIC_API_KEY environment variable set
  • PostgreSQL (required for the DB agent, REST API, and chat server; not needed for the Excel agent)

Installation

1

Clone the repository and install dependencies

git clone <repo-url>
cd clo-fund-agent-public
uv sync
2

Activate the pre-commit lint hook (once per clone)

git config core.hooksPath .githooks
3

Set your Anthropic API key

export ANTHROPIC_API_KEY=sk-ant-...
4

(DB agent only) Create the PostgreSQL schema and load fund data

# Create tables
psql -h /tmp -d postgres -f db/schema.sql

# Load all funds
uv run python db/load_data.py          # DKIG-2024-VII, DKIG-2016-I
uv run python db/load_ce_fund.py       # DKIG-2018-CE (Clean Energy)
uv run python db/load_tech_fund.py     # DKIG-2019-TECH (Technology)
Tip — Excel agent needs no database If you only want to query DKIG-2024-VII or DKIG-2016-I and have the CLO_Fund_Domain_Data.xlsx workbook, the Excel agent works with no PostgreSQL setup at all.
Usage

Entry Points

The system provides four ways to interact with fund data. Choose the one that fits your workflow.

1 — Excel Agent (no database required)

Reads directly from CLO_Fund_Domain_Data.xlsx. Best for quick exploration of DKIG-2024-VII and DKIG-2016-I without any infrastructure.

# Interactive REPL (recommended for multi-question sessions)
uv run python -m clo_agent

# One-shot mode
uv run python -m clo_agent 'What is the net IRR for DKIG-2024-VII?'

2 — PostgreSQL Agent

Reads from PostgreSQL. Supports all four funds and discovers new funds automatically. The REPL is significantly faster for interactive use due to prompt caching and connection pool reuse.

# Interactive REPL
uv run python -m clo_db_agent

# One-shot mode
uv run python -m clo_db_agent 'What is the net IRR for DKIG-2024-VII?'
REPL vs one-shot The REPL warms the Anthropic prompt cache after the first question, keeps the PostgreSQL connection pool open, and maintains a 5-minute in-memory data cache. One-shot starts cold every time and is best for scripted automation.

3 — REST API

FastAPI application exposing all eight data products as JSON endpoints. Suitable for integration into dashboards or downstream systems.

# Development server
uv run uvicorn clo_api.main:app --host 127.0.0.1 --port 8000

# Production (behind TLS-terminating proxy)
uv run gunicorn clo_api.main:app -w 4 -k uvicorn.workers.UvicornWorker \
    --bind 127.0.0.1:8000

Swagger UI available at http://127.0.0.1:8000/docs (disabled when ENVIRONMENT=production).

4 — Browser Chat UI

Streaming chat interface served over HTTP. Wraps the DB agent with Server-Sent Events for real-time response streaming.

# Default port 7860
uv run python clo_chat_server.py

# Custom port
PORT=8080 uv run python clo_chat_server.py

Open http://localhost:7860 in your browser. The agent query endpoint is at /ask.

5 — Multi-Agent Orchestrator

For complex, multi-product analysis tasks (e.g. full distribution authorisation reports). Dispatches specialist agents in parallel. See the Multi-Agent section for details.

uv run python -m multi_agent

Authentication

# Set the API key environment variable before starting the server
export CLO_API_KEY=your-secret-key

# Include the header in every request
curl -H "X-API-Key: your-secret-key" \
     http://127.0.0.1:8000/funds/DKIG-2024-VII/performance/latest
Production deployment Set ENVIRONMENT=production to disable Swagger UI and ReDoc. CLO_API_KEY is mandatory in production — the server will exit at startup if it is unset. Always run behind a TLS-terminating reverse proxy.

Rate Limiting

The API enforces a limit of 60 requests per minute per IP address. Requests exceeding this limit receive an HTTP 429 response.

Advanced

Multi-Agent System

The multi_agent/ package provides an orchestrator-plus-specialist architecture for complex, multi-product analysis tasks such as full distribution authorisation reports. It is distinct from the single-agent clo_db_agent — use it when you need synthesis across multiple data products in a single response.

Specialist Agents

Portfolio Agent

Reads DP-02 (loan positions) and DP-07 (WARF, WAS, WAL, diversity score).

Performance Agent

Reads DP-03 (NAV, IRR, DPI, RVPI, TVPI, period P&L).

Compliance Agent

Reads DP-04. Must run before the cashflow agent per the Waterfall Priority Axiom.

Cashflow Agent

Reads DP-05. Uses compliance gate output to model distribution vs. diversion.

Fee Agent

Reads DP-06 (management, incentive, trustee, admin, tax fees).

Optimizer Agent

Runs the portfolio return optimizer. Only dispatched when OC cushion is thin (< 100 bps) or explicitly requested.

Reporting Agent

Reads all session memory and synthesises the final structured memo.

Distribution Authorisation Workflow

The orchestrator follows a defined workflow for distribution tasks:

1

Call list_available_funds if no fund is specified.

2

Parallel: dispatch portfolio, performance, compliance, and fee agents simultaneously.

3

Sequential: dispatch cashflow agent — uses the compliance gate result to determine distribution vs. diversion path.

4

Conditional: dispatch optimizer agent only if OC cushion < 100 bps or a breach exists.

5

Dispatch reporting agent to synthesise all session memory into the final memo.

Session memory All specialist agents write their outputs to multi_agent/session_memory/. The reporting agent reads from this shared store to compile the final memo. A consistent session_date is used across all agent calls in one orchestration run.
Analytics

Portfolio Optimizer

The portfolio_optimizer/ module implements a greedy hill-climbing optimizer that maximises equity spread yield subject to all covenant constraints. It is exposed as the optimize_portfolio_returns tool in the DB agent.

How It Works

  1. Loads the current portfolio from DP-02 and covenant thresholds from DP-04.
  2. Pre-filters candidate trades: only sell a lower-spread position into a higher-spread one.
  3. Evaluates all pairwise sell/buy combinations at sell fractions of 25%, 50%, or 100%.
  4. Accepts a trade only if it simultaneously improves equity yield AND all compliance tests still pass.
  5. Applies the best qualifying trade, then repeats — up to 150 iterations.
  6. Returns the full accepted-trade sequence, per-iteration compliance detail, and the final portfolio state.

Output Structure

FieldDescription
baseline_equity_yield_pctEquity spread yield before any optimisation
final_equity_yield_pctEquity spread yield after all accepted trades
total_yield_improvement_ppAbsolute improvement in percentage points
accepted_tradesOrdered list of every accepted sell/buy pair with compliance detail
final_portfolioFull loan-level portfolio after all trades are applied
convergedTrue if the optimizer found no further improving trade; false if the 150-iteration cap was hit
recommendation_reasonPlain-English summary of why the recommended trade sequence was chosen
Caveat — equity yield is a proxy metric The optimizer uses a spread-over-SOFR proxy for equity yield. The absolute percentage is not the fund net IRR. Yield deltas between scenarios are accurate and directly comparable. Always verify final figures against DP-03 (Net IRR) and DP-04 (Compliance Dashboard) before acting on recommendations.

Loan Replacement Simulation

For one-off what-if analysis, use simulate_loan_replacement directly:

  • What happens to WARF, WAS, and WAL if I replace position P0023 with a B1-rated loan at 350 bps maturing 2030-06-15?

The tool removes the specified position, adds a synthetic loan with your parameters, and returns before/after values plus deltas for all three metrics.
